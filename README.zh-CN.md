# AI Coding Guardrails Skill

[English](./README.md) | 简体中文

一个轻量级 AI 编码 Skill，用于让代码改动保持最小、聚焦、明确且可验证。

## 这是什么？

AI Coding Guardrails Skill 是一个用于约束 AI 编码助手行为的实用 Skill。

它的目标是让 AI 在写代码、改代码、修 bug、重构或添加功能时，更加克制、清晰、可审查。

它可以帮助 AI 编码助手：

* 在实现前说明假设
* 优先选择简单方案
* 只做最小必要改动
* 避免无关重构
* 避免过度设计
* 定义清晰的成功标准
* 通过测试或检查验证结果

## 为什么需要这个 Skill？

AI 编码助手很强大，但在真实工程流程中也容易产生问题。

常见问题包括：

* 没有说明假设，直接开始修改
* 修改了与需求无关的文件
* 顺手重构原本不需要修改的代码
* 添加不必要的抽象
* 把简单问题复杂化
* 缺少验证步骤
* 生成过大的 diff，导致难以 review

这个 Skill 提供了一组实用的工程约束，让 AI 生成的代码改动更加聚焦、可控、可审查。

## 核心原则

### 1. 先思考，再写代码

在实现之前，AI 应该先清楚说明自己的理解和假设。

如果需求存在歧义，AI 应该指出歧义，而不是静默选择其中一种解释。

### 2. 简单优先

AI 应该只写解决当前问题所需的最少代码。

不添加投机式功能，不为单次使用场景设计抽象，也不增加没有被要求的配置能力或灵活性。

### 3. 外科手术式改动

AI 应该只修改和当前任务直接相关的代码。

不要顺手重构，不要清理无关代码，不要改动无关格式，也不要优化请求范围之外的内容。

每一行改动都应该能够追溯到用户的请求。

### 4. 目标驱动，可验证

每个代码任务都应该被转换成一个可验证的目标。

例如：

* 修 bug：先复现问题，再做最小修复，最后验证结果
* 加功能：先明确预期行为，再实现，最后检查
* 重构：确认重构前后行为一致，并通过测试或检查

## 什么时候使用这个 Skill？

当你希望 AI 帮你完成以下任务时，可以使用这个 Skill：

* 修改代码
* 添加功能
* 修复 bug
* 重构已有代码
* 审查实现计划
* 控制改动范围
* 保持 diff 小而清晰
* 避免过度设计
* 避免无关代码改动
* 在编码前说明假设
* 在修改后提供验证方式

## 什么时候不适合使用？

这个 Skill 可能不适合以下场景：

* 开放式架构探索
* 大规模代码重写
* 宽泛的产品创意发散
* 目标不明确的实验性原型
* 更需要发散创造力，而不是严格控制范围的任务

对于探索型工作，可以先自由讨论方案；当实现目标明确后，再使用这个 Skill 来约束具体代码改动。

## 使用方式

将 `SKILL.md` 的内容添加到支持 Skill、规则、自定义指令、项目指令或项目级配置的 AI 编码工具中。

这个 Skill 适合用于以下工具或工作流：

* ChatGPT
* Claude
* Cursor
* Windsurf
* Claude Code
* 其他 AI coding agent 或开发辅助工具

不同工具的配置方式可能不同，但核心目标是一致的：

让 AI 在处理代码相关任务时遵守 `SKILL.md` 中定义的规则。

## 示例提示词

你可以这样使用：

```text
- state assumptions first
- make only the minimum necessary changes
- avoid drive-by refactors

```

或者使用中文：

```text
请按照 AI Coding Guardrails Skill 的原则修改代码：
- 先说明假设
- 只做最小必要改动
- 不要顺手重构
- 修改后说明如何验证
```

也可以用于修 bug：

```text
请使用 AI Coding Guardrails Skill 来修复这个 bug。
先说明可能原因，再做最小修复，最后给出验证步骤。
```

## 设计理念

AI 编码助手不应该默认进行大范围重写、投机式抽象或无关优化。

一个好的 AI 编码协作者应该：

* 理解需求
* 说明假设
* 控制范围
* 保持 diff 可审查
* 验证修改结果

这个 Skill 的目标不是让 AI 写更多代码。

而是让 AI 写更少、更准、更可靠的代码。
